# 0.1.50 — correlate command acknowledgements without consuming touch reports

A manufacturer-specific touch report sharing a ZCL transaction number could
satisfy zigpy's generic request future. MoSwitch then called that76-byte report
a rejected command, including0x44 when entering manual adjustment.

Commands now retain APS acknowledgement and DefaultResponse requests while
bypassing the generic TSN-only response future. A temporary listener on the
selected Basic cluster validates transaction number, direction, manufacturer,
original command and typed DefaultResponse. Reports reach normal telemetry
listeners. Actual device rejections remain errors; cleanup covers cancellation
and timeout. A matching ZCL reply is retained if the APS confirmation is lost.

The existing per-device snapshot includes the already received status-light
preference/error state and its timestamp, without new controls, entities or
retired hardware test fields. Firmware and saved calibration are unchanged.

Validation:88 pytest tests, Ruff, clean-main package. Regression dispatch uses
real zigpy Basic clusters, same-TSN touch telemetry, unrelated replies, explicit
rejection, timeout, cancellation and lost APS confirmation. ZCL payloads and
ACK-request flags remain unchanged; target readback follows HACS installation.
Build:python3 tools/package.py; metadata:dist/0.1.50/.
